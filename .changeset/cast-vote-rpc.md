#126: added `public.cast_vote(p_venue_id)`, a `SECURITY DEFINER` Postgres RPC that enforces the 3-vote/day cap (global per user, #62/#134) and per-venue dedup atomically, inside the transaction — closing the gap where the equivalent check in `apps/api/src/services/vote.service.ts` only protects the Fastify path, which isn't deployed for this beta and is trivially bypassable via PostgREST's auto-generated `POST /rest/v1/votes` using the client-bundled anon key. Also introduced `public.vote_day(at, tz)`, a canonical SQL port of `packages/shared-types/src/voteDay.ts`'s `voteDayFor` (04:00 city-local boundary, `America/New_York` default), and re-pointed 0006's `recalculate_hotspot_scores()` at it via `CREATE OR REPLACE` (0006 itself is left immutable) — fixing a day-boundary mismatch where the trending list's `daily_count` and the vote budget disagreed for a 4-hour window every night. `cast_vote` also now owns `venues.vote_count`, deliberately left unmaintained by 0006. Shipped as `apps/api/drizzle/0007_cast_vote_rpc.sql`, recorded in `apps/api/drizzle/meta/_journal.json` and `0007_snapshot.json` via `drizzle-kit generate --custom`, matching the 0005/0006 convention. EXECUTE is revoked from `PUBLIC` and `anon` and granted only to `authenticated` (which covers this beta's anonymous-sign-in users); `auth.uid()` is the sole source of voter identity. Verified against a scratch local Postgres 16 (cap exhaustion, dedup, global-not-per-city scope, `vote_count` increments, the 03:59:59/04:00:00 boundary matching `voteDayFor`/`voteDayResetAt` exactly, concurrent-request cap enforcement via `pg_advisory_xact_lock`, and ACL survival across `CREATE OR REPLACE`) — nothing applied to the live Supabase project (connector unauthorized this session). Adds an opt-in Vitest integration suite (`apps/api/tests/db/cast-vote-rpc.test.ts`, gated on `TEST_DATABASE_URL`, skipped by default) covering cap exhaustion and duplicate-vote rejection against the real migration SQL.
